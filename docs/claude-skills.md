# Claude Code スキル

本プロジェクトでは、Claude Code のカスタムスキルを2つ運用しています。いずれも「動くテストコードこそが第一級の仕様書である」という思想に基づいています。

## スキル一覧

| スキル名 | 場所 | 用途 |
|----------|------|------|
| test-spec-checker | `.claude/skills/test-spec-checker/` | テストの仕様カバレッジ監査 |
| doc-maintainer | `.claude/skills/doc-maintainer/` | テストに基づくドキュメント保守 |

---

## test-spec-checker

テストスイートが「生きた仕様書」として機能しているかを監査するスキル。

### 目的

- **仕様ギャップの検出**: テストのない公開APIを特定
- **矛盾の検出**: テストの期待値と実装の動作が食い違う箇所を特定
- **古いテストの検出**: 削除・変更されたコードに対する陳腐化テストを特定
- **エッジケースの不足**: テスト済み関数で未カバーのシナリオを特定

### 使い方

```
# モジュール単位
modelsモジュールのテスト仕様カバレッジをチェックして

# レイヤー単位
coreのテストと実装に矛盾がないか確認して
CLIの仕様カバレッジをチェックして

# リポジトリ全体
リポジトリ全体のテスト仕様カバレッジを監査して
```

### スコープ対応表

| 指定 | ソース範囲 | テスト範囲 |
|------|-----------|-----------|
| 全体 / all | `src/mcpax/` | `tests/` |
| core | `src/mcpax/core/` | `tests/unit/test_*.py` |
| cli | `src/mcpax/cli/` | `tests/unit/test_cli.py` |
| tui | `src/mcpax/tui/` | `tests/unit/tui/` |
| models, api 等 | `src/mcpax/core/<module>.py` | `tests/unit/test_<module>.py` |

### 監査プロセス

4つのフェーズで実行されます：

1. **インベントリ**: ソース・テストから公開APIとテスト対象を抽出
2. **ギャップ分析**: テストのないAPI、不足エッジケースを特定
3. **矛盾検出**: テストの期待値と実装の動作を比較（最重要フェーズ）
4. **陳腐化チェック**: 古くなったテストを特定

### 出力

日本語のマークダウンレポートが出力されます。矛盾 > 仕様ギャップ > エッジケース > 陳腐化テストの優先順で整理され、各項目にはソースコードとテストコードの行番号が付記されます。

## doc-maintainer

テストと実装コードから仕様を抽出し、ドキュメントを保守するスキル。

### 目的

- **ドキュメント鮮度チェック**: コード・テストと現在のドキュメントの差異を報告
- **既存ドキュメントの更新**: 古くなった記述をテスト・実装に基づき修正
- **新規ドキュメント作成**: 未ドキュメントの機能について新たにドキュメントを生成

### 使い方

```
# 鮮度チェック（レポートのみ、編集なし）
READMEが古くなってないかチェックして

# ドキュメント更新
CLIのドキュメントを最新の実装に合わせて更新して

# 新規作成
TUIの使い方ガイドを書いて
```

### 仕様抽出元

| 情報源 | 抽出する内容 |
|--------|-------------|
| `tests/unit/test_cli.py` | コマンド、オプション、出力形式、エラー動作 |
| `tests/unit/tui/` | 画面構成、キーバインド、ウィジェット動作 |
| `tests/unit/test_*.py` | 公開メソッド、パラメータ、戻り値、エラー契約 |
| `src/mcpax/cli/app.py` | CLI デコレータ、デフォルト値 |
| `src/mcpax/tui/` | 画面遷移、ウィジェット構成 |

### 出力

- **鮮度チェック**: 日本語の差異レポート（要更新箇所 + 最新の箇所をテーブル形式で）
- **更新**: 既存ドキュメントを直接編集（変更理由とテスト根拠を明示）
- **新規作成**: 日本語のマークダウンドキュメント（画面遷移図はMermaid記法を使用）

## 開発経緯

両スキルとも、テストプロンプトによる評価（with_skill vs without_skill のベースライン比較）を2イテレーション実施して品質を検証しました。

### 評価結果サマリー

| スキル | with_skill 合格率 | without_skill 合格率 | 改善幅 |
|--------|-------------------|---------------------|--------|
| test-spec-checker | 100% | 75% | +25% |
| doc-maintainer | 100% | 67% | +33% |

主な差別化要因は **test_based_evidence**（テストファイル名・行番号を根拠として引用するかどうか）です。スキルありの場合は一貫してテストを根拠として引用しますが、スキルなしでは実装コードの参照にとどまり、テストを仕様の出典として引用しない傾向があります。
